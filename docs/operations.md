# Работа с новыми данными: другие годы и города

Инструкция для запуска во внутреннем контуре на данных того же формата. Всё работает без сети.

## 1. Данные города

Каталог `data/regions/<код>/` с тремя файлами:

| Файл | Содержимое |
|---|---|
| `cases.xlsx` | недельные обращения с ОРВИ и численность населения по группам (`Дата`, `Всего_орви`, `0 - 2_орви`, …, `Всего`, `0 - 2`, …) |
| `pcr.xlsx` | число протестированных на грипп и положительных по подтипам (`Дата`, `Число образцов тестированных на грипп`, `A (субтип не определен)`, `A(H1)pdm09`, `A(H3)`, `B`) |
| `meta.json` | `{"name_ru": "Томск", "district": "Томск"}` — название для отчёта и название города в общероссийской выгрузке ПЦР (по нему подключается возрастная ПЦР); если файла нет, берутся встроенные значения или код каталога |

**Из «сырых» выгрузок** (`Заб <город>.xlsx`, `ПЦР <город>.xlsx`: многоуровневый заголовок, испорченные Excel
заголовки групп `3-Jun`/`Jul-14` или даты, неразрывные пробелы в метках недель):

```bash
python scripts/convert_raw_regions.py --code tomsk --name Томск --cases "Заб Томск.xlsx" --pcr "ПЦР Томск.xlsx"
```

Конвертер проверяет порядок групп в каждом блоке и падает с понятной ошибкой, если формат другой. Пропуски
ПЦР в середине ряда интерполируются (`--pcr-gap-policy interpolate`, по умолчанию) и помечаются; последние
недели без ПЦР отбрасываются.

**Новые годы того же города** — просто более длинные `cases.xlsx`/`pcr.xlsx` (или повторная конвертация
сырых файлов). Ничего не зашито под конкретные годы: сезоны, ISO-недели (включая 53-недельные годы) и
праздничные недели определяются по датам.

## 2. ПЦР по возрастам (общероссийская выгрузка)

```bash
python scripts/convert_age_pcr_export.py export_LABD_PCR_weekly_201840_201939.xlsx
```

создаёт `data/national/age_pcr_2018w40_2019w39.csv`. Загружаются все `age_pcr_*.csv` каталога; для недель,
где по городу протестировано ≥ 20 проб по всем группам, возрастные ряды строятся по возрастной доле
положительных, иначе — в допущении одинаковой доли (`docs/age_groups.md`).

## 3. Запуск

```bash
ai4epi run-analysis-local --city tomsk --end-date 2025-01-20 --mechanistic-wave --br-age-groups --age-forecast
```

Если у города нет численностей 15–64 / 65+, возрастная модель БР автоматически переходит на матрицу авторов
0–6 / 7–14 / 15+ (нужны группы 0–2, 3–6, 7–14, 15+), а без них — на матрицу 2×2; об этом пишется
предупреждение.

Не запускайте несколько анализов или бэктестов параллельно без ограничения потоков: обучение HGB
использует все ядра, и два процесса на одной машине могут работать в десятки раз медленнее. Для
параллельных запусков задайте `OMP_NUM_THREADS` (например, 2 на процесс).

## 4. Полоса модели Барояна–Рвачёва для нового города или метода

Полоса прогноза модели БР по умолчанию строится по ошибкам её прошлых прогнозов
(`data/calibration/br_conformal.json`, `docs/mechanistic_wave.md`). Таблица в репозитории построена по
бэктестам 8 городов. Для своих данных или после смены метода калибровки её стоит пересчитать:

```bash
ai4epi backtest-local --city tomsk --start 2023-10-02 --end 2024-04-29 --output-dir runs/bt/tomsk_2023
ai4epi br-conformal-fit runs/bt/*/ --evaluate
```

`--evaluate` печатает покрытие при исключении каждого бэктеста — оно должно быть близко к номинальным 0.9.
Без таблицы показывается 5–95 % пучка траекторий с предупреждением, что он недооценивает неопределённость.
